## 実 API での 1 turn（2026-10-13 実行）

.env の OLLAMA_API_KEY を使い、headless で 1 turn を走らせた。

- 実行: bun packages/app/cli/src/run.ts --profile headless --patch .tmp/sessions.yml --model ollama-cloud/kimi-k2.7-code --json "Reply with the single word pong"
- 終了コード: 0（stderr は空）
- セッションログ（.tmp/sessions-ws/<id>/session.v1.jsonl）: session/header → agent/inbox/queued → turn/start → agent/inbox/claimed → step/start → system/message → user/message → request/header（provider=ollama-cloud, model=kimi-k2.7-code）→ assistant/message（本文は pong）→ step/end → turn/end（reason は { kind: completed }）
- セッションの保存先は --patch で .tmp/sessions-ws に移した（sandbox がホームディレクトリへの書き込みを許さないため）。base profile の root: ~/.fudo/sessions は JSONL provider が ~ を展開するようになった（expandHome）。

## 秘密情報の扱い（2026-10-13 決定）

- 保存は平文の secrets.env（XDG_CONFIG_HOME/fudo/secrets.env、無ければ ~/.config/fudo/secrets.env）、モード 600。グループや他人が読める場合は警告する。
- 入力は fudo auth add PROVIDER（サービス名で指定。ollama / openai を表に持つ）と fudo auth set ENV_NAME。端末では打鍵を隠し、パイプでも渡せる。list は名前だけ、remove で削除。
- 読み込みは起動時。シェル環境が最優先、次に secrets.env、次に cwd 祖先の .env（近いものが外側を上書き）。
- 暗号化はしない。理由: 実行時に平文の鍵が必要で、復号のパスフレーズも同じ環境に置くことになり守れる範囲が狭い。パスフレーズを忘れると鍵を失う確実なリスクと、毎回の入力や起動のコストを足す。守るべき「ログに鍵を出さない」は実測で確認済み（ダミーキーで 401 を起こし、セッション JSONL と stdout、stderr を grep して一致なし。鍵は Authorization ヘッダと検索 provider にのみ渡る）。
- 将来「保管時の保護」が必要になったら、パスフレーズではなく OS キーチェーン（macOS の security など）にマスターキーを預ける形にする。パスフレーズ方式の実装は一度書いたが未使用のため削除した（履歴には残っている）。
